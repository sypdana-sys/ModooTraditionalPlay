# 사방치기 VR 프로토타입 구현 가이드

이 문서는 `사방치기_구현_체크리스트.md`의 프로토타입 우선순위를 실제 Unity 작업 순서로 풀어 쓴다. 현재 범위는 1번 칸에서 망을 선택하고 투척한 뒤 성공·실패 결과를 확인하는 최소 루프다.

## 1. 적용 기준

- 세부 규칙은 `사방치기규칙_구체화.txt`를 기준으로 한다.
- 프로젝트 전체 방향은 `한국 전통놀이 VR 체험 기획서.pdf`를 참고한다.
- 실제 점프, 숙이기, 빠른 신체 회전은 프로토타입에 요구하지 않는다.
- 씬 배치, 컴포넌트 추가, UI 구성, Inspector 연결은 사용자가 수행한다.
- 코드 작업에는 저장소 루트 `AGENTS.md`와 `Assets/Script/AGENTS.md`를 함께 적용한다.

## 2. 프로토타입 완료 범위

프로토타입 1차 완료는 아래 흐름이 한 번 재현되는 상태다.

```text
Ready
  → 시작 UI에서 네 선택
  → SpawnPoint 이동
  → 1번 칸 위치 선택
  → 파워 게이지 왕복
  → 파워 확정
  → 망 투척
  → 성공 또는 실패 UI
  → 실패하면 위치 선택 재시작
  → 성공하면 MovingForward 이벤트 전달
```

전진 QTE, 180도 회전, 복귀, 망 줍기, 라운드 증가, 땅따먹기는 프로토타입 완료 후 구현한다. 해당 상태 이름과 이벤트 연결 지점은 먼저 준비할 수 있지만, 동작이 없는데 완료로 표시하지 않는다.

현재 저장된 코드와 씬 기준으로 1~6단계 구현 및 Inspector 참조 연결이 완료되어 있다. 7단계의 `Manual Movement Components`는 아직 비어 있으므로 일반 이동 잠금은 연결 전이며, 아래 Play Mode 검증 항목은 실제 실행 확인 후 별도로 체크한다.

## 3. 스크립트 책임

| 스크립트 | 프로토타입에서 담당할 기능 |
|---|---|
| `UIDoor` | 시작 확인 UI, 플레이어의 SpawnPoint 이동, 시작 요청 전달 |
| `SabangGameManager` | 전체 `GameState`, 시작 중복 방지, 현재 목표 번호, 이동 잠금, 투척 상태 전달 |
| `SabangStone` | Ray 위치 선택, 왕복 게이지, Rigidbody 투척, 착지·경계선 판정, 실패 재시도 |
| `Map` | Raycast 지점과 망 중심의 구역 조회 |

한 스크립트가 다른 스크립트의 private 상태를 직접 바꾸지 않는다. `SabangStone`은 결과를 이벤트로 알리고, 다음 단계 결정은 `SabangGameManager`가 담당한다.

## 4. 0단계, 씬 준비 확인

코드 작성 전에 다음 항목을 확인한다.

- [x] Unity 버전이 `ProjectSettings/ProjectVersion.txt`의 6000.3.10f1과 일치한다.
- [x] `SaBang.unity`에 `Map`과 `UIDoor`가 존재한다.
- [x] 놀이판 표면의 Layer와 실제 바닥 Layer를 구분할 수 있다.
- [x] 경계선용 Collider와 Layer를 별도로 지정할 수 있다.
- [x] 플레이어의 XR Origin과 Camera가 씬에 존재한다.
- [x] 오른손 컨트롤러의 Trigger Input Action을 확인했다.
- [x] 망에 Rigidbody와 Collider가 있으며, Rigidbody가 망 오브젝트에 붙어 있다.

현재 `SaBang.unity`에는 `SabangStone`과 `SabangGameManager`가 배치되어 있으며 서로 연결되어 있다. 씬 배치와 Inspector 연결을 변경할 때는 Unity Editor에서 직접 수행한다.

## 5. 1단계, 시작 흐름 연결

### Game Manager 설정

1. 빈 GameObject에 `SabangGameManager`를 추가한다.
2. `Stone`에 망 오브젝트의 `SabangStone`을 연결한다.
3. `Manual Movement Components`에는 일반 스틱 이동, 스틱 회전, 자유 텔레포트 입력 컴포넌트만 연결한다.
4. XR Origin, Input Action Manager, HMD·컨트롤러 추적, Trigger·Grip 입력 컴포넌트는 연결하지 않는다.

### Door 설정

1. 사방치기 시작 문인 `UIDoor`의 `Game Manager`에 매니저를 연결한다.
2. `XR Origin`과 `Spawn Point`를 연결한다. 비워 두면 코드의 이름 검색 fallback이 동작하지만, 프로토타입에서는 직접 연결을 권장한다.
3. `On Yes`에 `SabangStone.BeginRound()` 또는 `SabangGameManager.TryStartGame()`을 중복 연결하지 않는다. `UIDoor`는 연결된 매니저를 내부에서 시작한다.
4. `On No`는 필요할 때만 별도 취소 동작을 연결한다.

### 시작 조건

- `SabangStone.Start Automatically`를 끈다. 기존 씬·프리팹에 저장된 true 값은 Inspector에서 직접 확인한다.
- 시작 전 `SabangStone`는 `Idle`, `SabangGameManager`는 `Ready`여야 한다.
- 필수 참조가 없으면 UI를 닫지 않고 시작을 거부한다.
- SpawnPoint 이동이 성공한 뒤에만 `TryStartGame()`을 호출한다.
- 시작이 성공하면 목표 번호를 1로 초기화한다.

## 6. 2단계, 망과 투척 참조 연결

`SabangStone` Inspector에서 다음을 연결한다.

| 항목 | 연결 대상 | 확인 기준 |
|---|---|---|
| `Map` | 놀이판의 Map 컴포넌트 | 1번 칸 Ray 조회 가능 |
| `Stone Body` | 망 오브젝트의 Rigidbody | 스크립트와 같은 GameObject |
| `Stone Collider` | 같은 망의 Collider | `attachedRigidbody`가 Stone Body |
| `Throw Point` | 투척 시작 위치 Transform | 망 자식이 아닌 고정 위치 권장 |
| `Ray Origin` | 오른손 Ray 시작 Transform | 로컬 +Z가 조준 방향 |
| `Right Trigger` | 오른손 Trigger Button Action | Input Action이 활성화됨 |
| `Target Marker` | 선택 위치 표시 오브젝트 | 선택 가능한 경우만 활성화 |
| `Tile Layers` | Map 구역 Trigger Layer | 바닥·경계선 제외 |
| `Ground Layers` | 실제 바닥 Collider Layer | 망 안정화 감지 |
| `Border Layers` | 경계선 Collider Layer | 접촉 시 실패 기록 |

망 Rigidbody는 투척 중 물리 시뮬레이션이 가능해야 한다. `Collision Detection`은 빠른 비행에서 충돌을 놓치지 않도록 Continuous Dynamic을 권장한다. 바닥과 경계선의 반발력은 플레이 테스트에서 조절한다.

## 7. 3단계, 1번 칸 위치 선택

`SelectingPosition` 상태에서만 오른손 Ray를 조회한다.

1. `Physics.Raycast`의 Layer Mask에 `Tile Layers`만 사용한다.
2. Trigger 구역을 맞히도록 `QueryTriggerInteraction.Collide`를 사용한다.
3. `Map.TryGetRegion(hit, out region)` 결과가 `Tile1`인지 확인한다.
4. 1번 칸 안쪽이면 `Target Marker`를 hit 지점에 표시한다.
5. 경계선 근처·다른 칸·놀이판 밖에서는 marker를 숨기고 Trigger 입력을 무시한다.
6. Trigger는 누르고 있는 동안 반복 처리하지 않고, 놓았다가 다시 누른 순간만 확정 입력으로 처리한다.

위치 선택 단계에서 망 Rigidbody를 움직이지 않는다. `selectedPoint`에는 Ray hit 지점만 저장하고, 투척은 파워 확정 이후 한 번만 시작한다.

## 8. 4단계, 왕복 파워 게이지

`SelectingPower` 상태에서 게이지를 갱신한다.

- Slider 값은 0~1로 표시하고 실제 파워는 0~100으로 관리한다.
- `Mathf.PingPong` 또는 같은 결과를 내는 단순한 왕복 계산을 사용한다.
- 1번 칸의 `requiredPower`와 `tolerance`로 성공 구간을 계산한다.
- 성공 범위는 `requiredPower - tolerance`부터 `requiredPower + tolerance`까지 포함한다.
- 게이지 UI는 상태 진입·종료 시 한 번 갱신하고, 이동 중인 표시자만 필요한 주기로 갱신한다.
- Trigger를 놓았다가 다시 누르면 파워를 저장하고 게이지를 숨긴다.

파워가 성공 구간 밖이어도 투척 모션은 실행한다. 부족한 파워는 목표보다 짧게, 초과 파워는 목표보다 멀리 도착하도록 한다.

## 9. 5단계, 투척과 착지 결과

### 비행 계산

1. Throw Point에서 망을 초기화한다.
2. 파워 오차를 목표 방향의 거리 오차로 변환한다.
3. Rigidbody를 dynamic으로 전환하고 중력을 적용한다.
4. 목표 위치와 비행 시간을 기준으로 초기 속도를 계산한다.
5. 투척 중 Trigger 입력은 무시한다.

### 성공 조건

다음 조건을 모두 만족해야 한다.

- [x] 파워가 필요 파워 ± 허용 범위 안이다.
- [x] 망 중심이 목표 번호의 Tile 안에 있다.
- [x] 망이 Border Layer와 접촉하지 않았다.
- [x] 망이 바닥에 닿아 안정된 상태다.

### 실패 조건과 재시도

- [x] 파워 부족 또는 초과.
- [x] 다른 칸 착지.
- [x] 놀이판 밖 착지.
- [x] 경계선 접촉.
- [x] 비행 시간 초과 또는 안정화 실패.

실패 시 투척을 중간에 끊지 않는다. 착지 또는 timeout을 확인한 뒤 `실패` UI를 표시하고 실패 횟수를 한 번 증가시킨다. `Result Duration`이 지나면 망을 Throw Point로 돌리고 같은 목표 칸의 위치 선택으로 돌아간다.

## 10. 6단계, 상태 전달

`SabangStone.ThrowState`와 `SabangGameManager.GameState`를 매 프레임 비교하지 않고 상태 변경 이벤트로 연결한다.

| `SabangStone.ThrowState` | `SabangGameManager.GameState` |
|---|---|
| `Idle` | `Ready` |
| `Selecting` | `SelectingPosition` |
| `Charging` | `SelectingPower` |
| `Flying` | `Throwing` |
| `Result` | `Throwing` 유지 |
| `Complete` | `MovingForward` |

실패 결과가 표시되는 동안은 `Throwing` 상태를 유지한다. 재시도에서 `Selecting` 이벤트가 발생하면 `SelectingPosition`으로 돌아간다. 성공 이벤트는 현재 프로토타입에서 `MovingForward` 전환까지만 확인하고 실제 이동은 후속 구현에서 연결한다.

## 11. 7단계, 일반 이동 잠금

- 게임 시작 직전에 `Manual Movement Components`의 현재 enabled 값을 저장한다.
- 게임이 진행되는 동안 해당 컴포넌트만 비활성화한다.
- HMD·컨트롤러 추적, Trigger·Grip 입력, XR Origin 전체는 비활성화하지 않는다.
- QTE 이동에 사용할 별도 컴포넌트가 있다면 일반 이동 잠금 배열에서 제외한다.
- `StopGame`, 매니저 비활성화, 이후 `Cleared` 전환 시 저장한 enabled 값을 복원한다.
- 원래 비활성인 컴포넌트는 복원 후에도 비활성으로 유지한다.

빈 배열은 코드 오류가 아니지만 이동 잠금이 동작하지 않는 상태다. 프로토타입에서 이동 잠금을 확인하려면 실제 이동 컴포넌트를 연결해야 한다.

## 12. Play Mode 검증 시나리오

### 시작

- [ ] 시작 전 망 게이지와 marker가 숨겨져 있다.
- [ ] 시작 전 자유 이동이 가능하다.
- [ ] 시작 UI의 ‘아니오’는 게임을 시작하지 않는다.
- [ ] 필수 참조 누락 시 시작 UI가 유지된다.
- [ ] ‘네’ 선택 후 SpawnPoint로 이동하고 1번 위치 선택이 시작된다.
- [ ] 시작 버튼을 반복해서 눌러도 목표 번호가 재설정되지 않는다.

### 투척

- [ ] 1번 칸 내부에서 marker가 표시된다.
- [ ] 다른 칸을 가리키면 위치를 확정할 수 없다.
- [ ] Trigger를 계속 누르고 있어도 위치 확정과 파워 확정이 한 번씩만 발생한다.
- [ ] 파워 게이지가 0과 100 사이를 반복한다.
- [ ] 파워 부족은 짧게, 파워 초과는 멀리 날아간다.
- [ ] 성공 시 `MovingForward` 상태와 성공 이벤트가 한 번 발생한다.
- [ ] 실패 시 망 비행 후 실패 UI가 표시된다.
- [ ] 실패 횟수가 한 번만 증가한다.
- [ ] 실패 후 같은 목표 칸 위치 선택으로 돌아간다.
- [ ] 경계선 접촉은 실패한다.

### 이동 잠금

- [ ] 게임 시작 시 연결한 일반 이동 컴포넌트가 비활성화된다.
- [ ] 게임 중 HMD·컨트롤러 추적과 Trigger·Grip 입력은 유지된다.
- [ ] `StopGame` 후 시작 전 enabled 상태로 복원된다.
- [ ] 시작 전부터 비활성인 컴포넌트는 복원 후에도 비활성이다.

- 컴파일 결과와 Unity Play Mode 결과.
