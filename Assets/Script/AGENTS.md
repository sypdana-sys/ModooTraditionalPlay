# Unity C# 스크립트 작성 지침

이 파일은 `Assets/Script`의 C# 파일을 만들거나 수정할 때 적용한다. 저장소 루트 `AGENTS.md`의 빠른 시작 정보도 함께 따른다.

## 변경 전 확인과 범위

- 대상 스크립트, 호출부, 관련 씬·프리팹, 규칙 문서와 로그를 먼저 확인한다.
- 게임 동작에 영향을 주는 가정이나 해결되지 않은 사양 충돌은 사용자에게 알린다. 작은 모호함은 가장 단순하고 되돌릴 수 있는 해석을 택해 보고한다.
- 요청 범위에 직접 연결되는 최소 변경만 수행한다. 관련 없는 정리, 리팩터링, 자동 생성 방식 변경을 함께 하지 않는다.
- 새 기능은 현재 코드의 유사한 구현과 기존 역할 분리를 따른다. 한 번만 쓰는 기능을 위해 관리자, 상속 구조, 전역 캐시, 새 패키지를 추가하지 않는다.
- 새 C# 소스 파일의 첫 줄에는 역할을 설명하는 한 줄 한국어 주석을 넣는다. 프레임워크가 첫 줄을 요구하거나 주변 스타일상 부적절하면 생략한다.

## Unity 연결과 호환성

- 씬 배치, 컴포넌트 추가, UI 구성, Inspector 연결은 사용자가 담당한다. 스크립트는 필요한 참조를 `[SerializeField]`로 노출하고 연결 방법을 설명한다.
- 오브젝트와 컴포넌트 자동 생성은 사용자가 요청했을 때만 사용한다.
- `[SerializeField]` 필드명·타입·배열 순서, public 메서드, UnityEvent 인수, enum 값의 정수 순서는 씬과 프리팹 연결에 영향을 줄 수 있다. 변경 전 사용처를 검색한다.
- 직렬화 필드 이름을 바꿔야 하면 가능한 경우 `[FormerlySerializedAs]`로 기존 값을 보존한다. 재연결이 필요하면 항목을 명시한다.
- 실제 설정 누락을 설명하는 오류 메시지, 입력 중복 방지, 결과와 실패 횟수의 중복 처리 방지, 경계선 접촉 기록, 재시도 초기화, 이벤트 해제와 생성 리소스 정리를 제거하지 않는다.

## 사방치기 책임과 상태

- 현재 범위는 1인용 사방치기 8칸의 기본 플레이이다. 장구 모드는 독립적으로 유지한다. AI 물리, 전신 트래킹, 4칸 모드, 장애물, BPM 연동은 별도 요청 없이 추가하지 않는다.
- 실제 점프, 숙이기, 빠른 신체 회전을 요구하지 않는다. Trigger는 선택·투척·QTE, Grip은 망 줍기에 사용한다. 이동은 QTE 결과로 제어한다.
- `Map`은 구역 판정만, `SabangStone`은 목표 위치 선택·파워 게이지·망 비행·투척 결과만 담당한다. 이동 QTE, 회전, 복귀, 망 줍기, 라운드 진행은 별도 진행 코드가 담당한다.
- 입력 접수, 투척 연출, 착지 판정, 다음 게임 단계 전환을 분리한다. 비행 중에는 결과를 확정하지 않으며, 다음 단계는 명시적인 결과 메서드나 UnityEvent로 알린다.
- 진행 단계는 enum처럼 명시적인 상태로 표현한다. 경계선 접촉 여부처럼 독립적인 사실 외에 여러 bool 조합으로 단계를 표현하지 않는다.
- 다른 스크립트의 내부 상태를 여러 곳에서 직접 수정하지 않는다. 순환 의존과 추적하기 어려운 이벤트 연결을 피한다.

## 간소화와 성능

- 코드 줄 수가 아니라 동작을 유지한 채 중복, 불필요한 분기, 반복 실행 비용을 줄이는 것을 목표로 한다.
- 측정하지 않은 구조 개선을 성능 향상이라고 보고하지 않는다.
- `Update`와 `FixedUpdate`에서는 현재 상태에 필요한 계산만 한다. 반복 오브젝트·컴포넌트 검색은 Inspector 참조 또는 수명이 명확한 캐시로 대체한다.
- 물리 조회는 필요한 상태와 Layer로 제한한다. 조회 빈도를 낮출 때는 입력 반응성과 충돌 정확도를 함께 확인한다.
- 정적인 UI는 값이나 상태가 바뀔 때 갱신한다. 반복 루프의 임시 컬렉션·문자열 할당은 실제 할당 근거가 있을 때만 개선한다.
- 같은 판정과 초기화 로직은 한곳에서 관리한다. 깊은 조건 중첩은 조기 반환 또는 의미 있는 메서드로 정리한다. 가독성을 해치는 한 줄 압축은 하지 않는다.
- 파워, 허용 오차, 게이지 속도, 비행 시간 같은 플레이 조정값은 Inspector에서 조절 가능하게 유지한다.

## 검증과 보고

- 목표를 확인하고, 최소 변경을 적용한 뒤, 변경에 맞는 좁은 범위의 검증부터 실행한다.
- 컴파일, Unity Play Mode, 성능 측정 결과를 구분한다. 성능 수치는 측정 조건과 근거가 있을 때만 제시한다.
- 변경 후에는 Inspector 연결, 입력 중복 방지, 결과 이벤트 호출 횟수, 실패 후 초기화가 유지되는지 확인한다.
- 코드가 바뀌면 `git diff --check`를 실행한다. 검증이 불가능하면 시도한 명령과 이유를 정확히 보고한다.
- 커밋은 사용자가 요청했거나 작업 흐름에서 요구될 때만 만든다. 요청된 커밋은 하나의 논리적 변경만 담는다.
